    ## Prerequisites
    - "Dereso Software Portal" custom site must exist in the target BigFix instance. Create it via BigFix Console → Sites before using the dashboard.

    ## Opening the Dashboard
    Navigation path: BigFix Console → Dashboards → Dereso Fixlet Copier.
    On load, the dashboard calls initDashboard() which populates the Sites and Target Site dropdowns using EvaluateRelevance. If dropdowns are empty, check that your account has visibility to at least one site.

    ## Step-by-Step Workflow
    (Expand each of the 6 steps from instrBody with 2–3 sentences of detail):
    1. Load Fixlets — click the "Load Fixlets" button. Explain the Sites multi-select (Ctrl+click), the Search box (filters by name, ID, category, severity), and the page-size selector.
    2. Select a Source Fixlet — click the radio button on any row. Explain that the fixlet's XML, title, category, and action scripts are loaded into the edit fields automatically via API.Get.
    3. Review and Edit — describe the Title and Category fields; note that title defaults to the source fixlet name; explain that Source, SourceID, Domain etc. are in hidden checkboxes that default to safe values.

       | Mode | Description | When to Use |
       |------|-------------|-------------|
       | Single Action | Creates one DefaultAction from the selected script | When you want a clean, minimal copy |
       | Full Copy | Preserves all actions; promotes selected one to DefaultAction | When all original action variants are needed |
    5. Choose a Target Site — select from the Target Site dropdown (only Custom sites shown). For Phase 1, select "Dereso Software Portal".
    6. Clone — click "Clone Selected Fixlet". On success, the new Fixlet ID appears in the status bar. On failure, an alert shows the HTTP status and error.

    ## Overview
    One-paragraph summary: BigFix wizard dashboard implemented as a single HTML page within a BES XML Wizard element. All logic is client-side JavaScript running inside the BigFix Console browser (IE 9 compatibility mode). Uses BigFix console's built-in API object and EvaluateRelevance function — no external libraries.

    ## Global State
    Table documenting all 14 global variables (var currentItems through var selectedItemIndex) with name, type, and purpose. Source: fixlet_copier.ojo lines 42–56.

    ## Data Flow
    Numbered sequence of 5 events (from the interfaces block). For each step, state the function name, what it reads from global state, what it writes to global state, and what side-effect it causes (DOM update, API call, etc.).

    ## XML Building Strategy
    Document the CDATA vs. entity-escape split:
    - Content requiring CDATA (Description, ActionScript): cdataStart() + xmlCDataSafe(value) + cdataEnd()
    - cdataStart() and cdataEnd() are split strings to prevent XML parsers from consuming them: '<!' + '[CDATA[' and ']]' + '>'
    - xmlCDataSafe() escapes ]]> sequences within content to prevent CDATA premature termination
    - Other fields (Title, Category, etc.): xmlEscape() for entity encoding
    - Relevance: one <Relevance> element per non-blank line via buildRelevanceXml(); defaults to <Relevance>true</Relevance> if all lines blank

    ## BigFix API Surface
    Table of 3 endpoints used (GET sites, GET fixlet/…, POST fixlets/custom/…) with method, path template, purpose, success codes. Note: API object is provided by BigFix Console — no explicit auth code in the dashboard.

    ## EvaluateRelevance Convention

    ## IE Compatibility Notes

    - parseSourceFields() and parseActions() use ActiveXObject("Msxml2.DOMDocument.6.0") — IE-only
