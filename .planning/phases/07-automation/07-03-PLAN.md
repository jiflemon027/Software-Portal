<objective>
Build the root-server audit store from 07-CONTEXT.md D-05 and RESEARCH.md Pattern 5: a small
dedicated SQLite database holding one `RolePublishRun` row per Publish event plus the full
`RoleUsers` username snapshot for that run, written by a single CLM-safe PowerShell script that
the dashboard will later embed and run on the root server via a targeted `SingleAction` (D-07).

Purpose: D-05 makes this store — not the Computer Group's relevance text and not a JSON file —
the source of truth for "who holds which role", and NFR-03's audit trail. Plan 07-05's
drift-check job and plan 07-06's dashboard Save button both read/write it, so it must exist and
be proven correct before either is written.

Output: `scripts/Upsert-RolePublish.ps1` (the single source of truth for the DDL and the write
semantics) plus a Pester suite. The dashboard will carry a literal mirror of this script, in the
same way `fixlet_dispatcher.ojo` mirrors `Invoke-PrefetchStage.ps1`.

<interfaces>
<!-- Contracts this plan establishes. Plans 07-05 and 07-06 build against these directly. -->

scripts/Upsert-RolePublish.ps1 — parameter contract:
  -PayloadPath        [string] (mandatory) path to a UTF-8 JSON file, see payload shape below
  -DatabasePath       [string] (mandatory) full path to RolePublish.db on the root server
  -SQLDir             [string] (mandatory) directory containing sqlite3.exe
  -SqliteHelperPath   [string] (optional)  defaults to Sqlite-Helper.ps1 beside -DatabasePath
  -WhatIf             [switch] performs every read, emits the SQL it would run, writes nothing

Payload JSON shape (written by the dashboard, consumed here):
  { "role": "IT Operations", "published_by": "jfannon", "users": ["alice","bob"] }

Schema this script owns (root-server RolePublish.db):
  RolePublishRun(RunID INTEGER PK AUTOINCREMENT, Role TEXT NOT NULL, Published_by TEXT NOT NULL,
                 Published_on TEXT NOT NULL DEFAULT (datetime('now','localtime')),
                 UserCount INTEGER NOT NULL)
  RoleUsers(RUID INTEGER PK AUTOINCREMENT, RunID INTEGER NOT NULL REFERENCES RolePublishRun(RunID),
            Role TEXT NOT NULL, UserID TEXT NOT NULL)
  idx_roleusers_run  ON RoleUsers(RunID)
  idx_roleusers_role ON RoleUsers(Role)

Canonical "current membership of a role" query (plan 07-05 uses this verbatim):
  SELECT u.UserID FROM RoleUsers u
  WHERE u.RunID = (SELECT MAX(RunID) FROM RolePublishRun WHERE Role = @role)
  ORDER BY u.UserID
</interfaces>

`<interfaces>` block (`-PayloadPath`, `-DatabasePath`, `-SQLDir`, `-SqliteHelperPath`,
`-WhatIf`), `#Requires -Version 5.1`, `[CmdletBinding(SupportsShouldProcess=$true)]`.

Behaviour, in order:

1. **Resolve and dot-source the helper.** If `-SqliteHelperPath` is empty, default it to
   `Join-Path (Split-Path $DatabasePath) 'Sqlite-Helper.ps1'` — the same resolution
   `Assign-RoleMapping.ps1` already uses. Abort with a `[ABORT]` message and exit code `5401`
   if it is missing, and `5402` if `sqlite3.exe` is not found under `-SQLDir`.

2. **Read and validate the payload.** `Get-Content -Raw -LiteralPath $PayloadPath |
   ConvertFrom-Json`. Reject with exit code `5410` if: the file is missing, JSON parsing fails,
   `role` is null/whitespace, `published_by` is null/whitespace, or `users` is not an array.
   An **empty** `users` array is legal (it means "this role now has no members") and must be
   recorded as a run with `UserCount = 0` — do not treat it as an error. Normalise each username
   with `.Trim().ToLowerInvariant()`, drop empty entries, and de-duplicate while preserving a
   deterministic ordinal sort. Cap the list at 5000 entries and abort with `5411` above that
   (a sanity brake against a malformed payload).

3. **Ensure schema.** Create `RolePublishRun`, `RoleUsers` and the two indexes exactly as
   specified in `<interfaces>`, each via `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT
   EXISTS`. Mirror `Initialize-RoleDb.ps1`'s loop: probe `sqlite_master` first and emit
   `[SKIP] <name> already exists` or `[CREATE] <name> created`. Never `DROP`, never `ALTER` an
   existing column, never `INSERT OR REPLACE`.

4. **Write the run.** Insert one `RolePublishRun` row (`Role`, `Published_by`, `UserCount`;
   let `Published_on` take its `datetime('now','localtime')` default), read back the new RunID
   with `SELECT last_insert_rowid() AS id`, then insert one `RoleUsers` row per username with
   that RunID. Batch the user inserts in groups of at most 400 per `Invoke-SqliteCommand` call,
   matching the batching convention already established in `Import-AxoniousExport.ps1`.

5. **Parameterize everything.** Every role name, username and `published_by` value goes through
   `Invoke-SqliteCommand -Parameters @{...}`. There must be **zero** occurrences of a PowerShell
   variable interpolated directly into a SQL string in this file — no `"... VALUES ('$role')"`.

6. **`-WhatIf`.** Under `-WhatIf` the script performs the schema probe reads and emits every
   statement it would execute (with parameter values shown) via `Write-Host "[WHATIF] ..."`,
   and performs **no** writes — not even the `CREATE TABLE IF NOT EXISTS` statements.

7. **Exit codes and output.** `0` on success. On success print a single
   `[OK] RunID=<n> Role=<role> Users=<count>` line so the calling ActionScript's log is
   greppable. Use only cmdlets available under Constrained Language Mode — no `Add-Type`,
   no `System.Data.SQLite`, no `New-Object` on arbitrary .NET types.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Tampering | JSON payload parsing in `Upsert-RolePublish.ps1` | mitigate | Validate `role`/`published_by` non-empty and `users` is an array before any DB access; reject with distinct exit codes 5410/5411; cap the list at 5000 entries. |
| T-07-03-02 | Tampering | SQL construction (SQL injection via username or role) | mitigate | Every value goes through `Invoke-SqliteCommand -Parameters @{...}` / `ConvertTo-SqliteLiteral`; acceptance criteria assert zero interpolated variables in INSERT strings, and Task 2 ships an explicit `'); DROP TABLE RoleUsers;--` test. |
| T-07-03-03 | Repudiation | Who published a role and when | mitigate | `RolePublishRun.Published_by` + `Published_on` are NOT NULL; the store is append-only (no UPDATE, no DELETE, no `INSERT OR REPLACE`) so history cannot be silently rewritten. |
| T-07-03-04 | Elevation of Privilege | Arbitrary code execution via the script running as SYSTEM on the root server | mitigate | CLM-safe only: no `Add-Type`, no `New-Object` on arbitrary types, no `Invoke-Expression`; the payload is data (JSON), never script.
