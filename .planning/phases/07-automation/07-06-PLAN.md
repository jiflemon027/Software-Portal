D-04), the D-02 autocomplete backed by already-seen `sAMAccountName`s, the D-10 optional scope

complete, useful operation on its own — it records the intent and the audit trail, and Publish
(plan 07-07) is the separate, explicit act that changes live targeting.

about whether the SQLite audit write fires on **Save** (D-13) or on **Publish** (D-07). This plan
resolves it in favour of **D-13: Save writes the `RolePublishRun`/`RoleUsers` row.** D-07
describes only the *mechanism* — a root-server-targeted `SingleAction` carrying the embedded
`Upsert-RolePublish.ps1` — not the trigger. Putting the write on Save is what makes Save a
complete operation and what gives D-13's "review before it touches the fleet" something concrete
to review; Publish (07-07) then reads the already-saved snapshot rather than racing to write it.
Plan 07-07 must not add a second audit write.

including a byte-fidelity check between the dashboard's embedded script mirror and
`scripts/Upsert-RolePublish.ps1`.
