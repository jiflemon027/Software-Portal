<objective>
Establish ground truth for the three things this phase's generator is otherwise built on
assumption alone: (a) whether this BigFix version accepts the "belt-and-suspenders" six-element
`<ComputerGroup>` BES-XML body on `POST computergroups/custom/<site>` (RESEARCH Assumptions A1
/ A6, Open Question 2), (b) whether the literal `set of ("a";"b")` tuple form parses as valid
client relevance (A2), and (c) whether any live artifact from the retired Axonius pipeline
still exists on `gpbfs` before plan 07-09 archives its source files (A4, Open Question 3) —
plus whether `sqlite3.exe` is staged on the root server (A5).

Purpose: this repo has **never** created a BigFix Computer Group via REST. Every later plan in
this phase assumes a schema shape verified only against official docs and one third-party
example. Getting this wrong after the dashboard is written means reworking the generator.

Output: a re-runnable spike/audit script plus a findings document that 07-04 and 07-09 read.
</objective>

Create `.planning/phases/07-automation/07-SPIKE-RUNBOOK.ps1`, a PowerShell 5.1-compatible,
`#Requires -Version 5.1` script with parameters `-BESRootUrl` (default `https://localhost:52311`),
`-SiteName` (default `Dereso Software Portal`), `-Credential` ([pscredential], mandatory),
`-SQLDir` (default `C:\Program Files (x86)\BigFix Enterprise\BES Client\EC\sqlite`),
`-OutputPath` (default `.planning/phases/07-automation/07-SPIKE-FINDINGS.md`) and
`-SkipDelete` (switch, leaves the throwaway group in place for console inspection).

It performs four checks and writes every result into a markdown findings file at `-OutputPath`:

**Check A — ComputerGroup create/read/delete.** POST to
`$BESRootUrl/api/computergroups/custom/$([uri]::EscapeDataString($SiteName))` a
`<BES><ComputerGroup>` body containing all six elements in this order: `Title`
(`ZZZ-SPIKE-DELETE-ME`), `Domain` (`BESC`), `JoinByIntersection` (`true`), `IsDynamic`
(`true`), `EvaluateOnClient` (`true`), `SearchComponentRelevance Comparison="IsTrue"` whose
`Relevance` CDATA is the Check-B expression below. Record the HTTP status and the full response
body. On non-2xx, retry once with a reduced body that omits `IsDynamic` and `EvaluateOnClient`
(the jgstew real-world shape cited in RESEARCH Pattern 1) and record which shape succeeded —
this is the single most important output of the script. On success, parse the new group id,
`GET computergroup/custom/<site>/<id>` and record the server's normalized round-trip XML, then
`DELETE computergroup/custom/<site>/<id>` unless `-SkipDelete`.

**Check B — literal set-of-tuple relevance.** Use the relevance
`(number of (logged on users whose (name of it as lowercase is contained by set of ("zzzspikeuser1";"zzzspikeuser2")))) = 1`
as Check A's group relevance, and additionally `POST $BESRootUrl/api/query` with
`relevance=` that same expression wrapped so it evaluates server-side where possible; record
whether BigFix returns a parse error or a boolean/empty result. A parse error here invalidates
RESEARCH Assumption A2 and must be called out explicitly in the findings.

**Check C — retired-pipeline orphan audit.** `schtasks /query /TN DeresoRoleIngest` and
`/TN DeresoRolePublish` (record exit code and output — "cannot find" is the expected/good
answer); `GET $BESRootUrl/api/fixlets/custom/<site>` and record every `<Name>` whose text
matches `RoleRef` or `Dereso Role Ref` (case-insensitive); `GET $BESRootUrl/api/computergroups/custom/<site>`
and record every group name matching `roleref` (case-insensitive). Any hit means plan 07-09's
archival must also stop/delete a live object rather than just moving files.

**Check D — root-server sqlite3.exe.** `Test-Path (Join-Path $SQLDir 'sqlite3.exe')` and, when
present, `& sqlite3.exe -version` — record the reported version against the pinned 3.53.1.

Use `Invoke-WebRequest` with a basic-auth header built from `-Credential`; prefer
`-SkipCertificateCheck` when `$PSVersionTable.PSVersion.Major -ge 6` and fall back to the
`ServicePointManager` trust-all shim used by `Publish-RoleSnapshot.ps1` on 5.1 — no `Add-Type`,
no `System.Data.SQLite`. Every check must be wrapped so a failure in one does not abort the
others; write `PASS` / `FAIL` / `SKIPPED` plus the raw evidence for each into the findings file.
