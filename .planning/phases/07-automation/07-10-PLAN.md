Execute D-15's archival and close every loose end it creates: move the retired dashboards,
scripts, modules, BES template and config files into `archive/` subfolders, relocate the test
suites whose subjects moved, strip the now-dead references out of
`Register-AutomationTasks.ps1`, `Invoke-WhatIfAudit.ps1` and
`config/PipelineConfig.defaults.json`, and rewrite the admin documentation for the
Operator-Role-Group model.

Purpose: leaving dead rows in `$AutomationTaskTable`, dead keys in `PipelineConfig`, and green
tests whose subjects no longer exist in their normal location is exactly the maintainability
smell that makes a future reader believe the Axonius pipeline is still live.

**Plan-time decisions recorded here:**
1. **Test fate (resolves RESEARCH.md's open question and 07-VALIDATION.md's Wave-0 item).** The
   suites whose subjects are archived move to `tests/archive/{unit,pester}/` as **frozen
   snapshots** — not deleted, and not left in the default run. Deleting them discards real
   coverage of code that still exists in the tree; leaving them in `tests/unit`/`tests/pester`
   means the "full suite green" gate keeps asserting behaviour of a retired design. A
   `tests/archive/README.md` records that they are historical and unmaintained.
2. **`$AutomationTaskTable` APPEND-ONLY exception (RESEARCH Pitfall 8).** The
   `DeresoRoleIngest` and `DeresoRolePublish` rows are **removed**, not left as dead entries
   pointing at archived scripts. This is an explicit, documented exception, justified because
   this phase is a pipeline replacement rather than an incremental addition — which is what the
   append-only rule was written for.
3. **`scripts/Initialize-AutomationDb.ps1` is NOT changed structurally.** Its 11-table DDL stays:
   the content pipeline still uses `SyncRun`/`PipelineConfig`/`ContentItem`/`ContentCache` in
   that same database, the seven role tables are idempotent and harmless, and dropping tables is
   a destructive change outside D-15's named scope. Only the `PipelineConfig` seed list changes
   (decision 4) plus a header comment marking the seven role tables as retired.
4. **Dead `PipelineConfig` keys are removed** (RESEARCH left this to the planner). Six
   Axonius-only keys go — `AxoniousExportPath`, `MaxExportAgeDays`, `SnapshotOutputDir`,
   `SnapshotUrlBase`, `UsernameSourcePriority`, `ConsoleUserRelevance`. The remaining seven —
   `BESRootUrl`, `AKeylessTokenFile`, `AKeylessSecretPath`, `BESOperatorUser`, `ValidityMonths`,
   `SQLDir`, `AlertWebhook` — are all still read by live code.

Output: a tree with no live reference to the retired design, a green default test run, and
documentation that matches what was actually built.
</objective>
