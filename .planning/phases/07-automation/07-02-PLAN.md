<objective>
Turn the reference database into something endpoints actually consume: publish one compact
JSON snapshot per published region into the BigFix Custom Repository with a `.sha1` manifest,
keep the per-region policy Fixlet's prefetch line in sync every run, and reconcile the console
user's roles into the endpoint's local `RoleAwareness.db` — with the region checked twice and
the D-12 upsert discipline preserved exactly.

Purpose: this is the distribution mechanism that replaces the rejected per-ComputerID design.
Roles follow the user; region scoping is done by the endpoint's own `GPC_Sub_Name` client
setting, so no ComputerID appears anywhere.

Output: `scripts/SnapshotBuild.psm1`, `scripts/Publish-RoleSnapshot.ps1`,
`scripts/Reconcile-LocalRoles.ps1`, `bes/RoleRef-Policy-template.bes`,
`scripts/Register-AutomationTasks.ps1` plus exported task XML, the D-19 `RoleDB_Maintenance`
rewiring, and three Pester suites.

Discretion resolution applied (07-RESEARCH.md § Discretion Resolutions, row 4): the per-region
policy action DOES carry the minimal freshness gate in v1. Without it, a host where the console
user never logs off silently stops being renewed and every role expires at `Valid_to` six
months later. Cost is roughly three lines of relevance plus one client-setting write.
</objective>

scripts/SnapshotBuild.psm1 exports:

  Build-RegionSnapshot -Rows <object[]> -Publication <object[]> -Region <string> -RunId <string> -ValidityMonths <int>
    Pure. $Rows are UserRole rows (UserID, Role, Active). $Publication are RolePublication rows
    (Role, RegionID, Active) already joined to a region name, where a NULL RegionID means all
    regions. Returns [pscustomobject] with properties run_id, region, built_on (ISO 8601 Z),
    validity_months, roles (array of @{ role; users }) where users is DISTINCT and sorted.

  New-PrefetchLine -FileName <string> -Sha1 <string> -Size <long> -UrlBase <string>
    Pure. Returns the single line:
    prefetch <FileName> sha1:<sha1> size:<size> <UrlBase>/<FileName>

  New-RoleRefRelevance -Region <string> -IncludeFreshnessGate <bool>
    Pure. Returns the combined single-string client relevance: the RoleAwareness.db existence
    guard AND the GPC_Sub_Name region gate AND (optionally) the freshness gate.

Snapshot file names (per published region, region lower-cased in the file name):
  roleref-<region>-<yyyyMMdd>.json
  roleref-<region>-latest.json
  roleref-<region>-latest.json.sha1

Snapshot body (D-11):
  { run_id, region, built_on, validity_months, roles: [ { role, users: [...] } ] }

scripts/Reconcile-LocalRoles.ps1 parameters (endpoint, PS 5.1, CLM-safe):
  -ConsoleUser -Region -SnapshotDir -SQLDir -DatabasePath -ValidityMonths -SqliteHelperPath -WhatIf
  -ConsoleUser is the test seam; when blank the script falls back to the explorer.exe/GetOwner
  query for the logon-task path, which has no relevance engine.

Client setting written on success: roleref_<region-lc>_applied = snapshot.built_on
Map columns written: Source_Type, Source_Value ('|'-joined), Region, Assigned_By='AxoniousSync'

Scheduled task names: DeresoRoleIngest (daily), DeresoRolePublish (daily, after ingest)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Root-server file system → BES web root | The snapshot becomes HTTP-reachable content the whole fleet downloads |
| BES web root → endpoint | An untrusted-until-verified JSON file crosses onto every managed client |
| Snapshot JSON → endpoint `RoleAwareness.db` | External data drives a privilege-granting write |
| Snapshot / role values → ActionScript | External strings are substituted into a script the client executes |
| `Publish-RoleSnapshot.ps1` → published BigFix content | A scheduled script mutates a live Fixlet every day |
| Endpoint region client setting → targeting | The client asserts its own region; nothing above it verifies that assertion |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Tampering | Snapshot JSON in the Custom Repository | mitigate | `.sha1` manifest written alongside; the policy Fixlet's `prefetch` line pins the hash so BigFix refuses a swapped file; the reconcile re-validates `snapshot.region` before applying. Write access to the roleref directory is root-server local admin — a pre-existing boundary |

| T-07-02-04 | Tampering | Role or group value injected into ActionScript | mitigate | Role and user values never reach ActionScript — the ActionScript only carries `{name of current user}`, `{value of setting "GPC_Sub_Name"}`, and fixed paths. `Reconcile-LocalRoles.ps1` arrives as a prefetched file resource, not an embedded `createfile` block, eliminating the brace-escaping and injection surface entirely (RESEARCH Pitfall 11) |
