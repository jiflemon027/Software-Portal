<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin input → XML (category "other" field) | Free-form text typed by admin enters fixlet XML via getEffectiveCategory() |
| Role values → Relevance expression | Role names from config are embedded as quoted strings in BigFix Relevance syntax |
| Fixlet XML → BigFix REST PUT | Constructed XML sent to BigFix API, persisted server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | category __other__ input → getEffectiveCategory() → catNodes[0].text | accept | MSXML .text property auto-escapes on assignment; value goes into XML text content, not innerHTML. Low risk: admin-only dashboard. |
| T-02-02 | Tampering | Role names → buildRoleRelevance() relevance expression | mitigate | Roles come exclusively from PORTAL_CONFIG.roles (admin-controlled constant, not end-user input). Role names are embedded as quoted strings; a double-quote in a role name would break Relevance syntax — mitigated by closed dropdown enforcing config-only values (D-07 per plan task 2). |
| T-02-03 | Tampering | fixlet PUT to wrong site | accept | PUT path is constructed from currentItem.siteName loaded from BigFix API at page load; admin cannot alter the target site without modifying loaded data in the browser. BigFix auth enforces write permission at API level. |
| T-02-04 | Denial | Stale MIME field data after failed PUT | accept | saveFixlet() updates in-memory allItems cache only on HTTP 200/201; on failure, local state unchanged and admin sees error alert. |
| T-02-SC | Tampering | npm/pip installs | accept | Phase 2 installs zero packages — no slopcheck required. |
</threat_model>
