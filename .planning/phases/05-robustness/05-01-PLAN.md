# Plan 05-01 — Role-Aware Web Report

## Goal

Deliver `Dashboard_4_samples/RoleAwareness_Report.beswrpt` — a BigFix Web Report that
shows all role-aware fixlets in the Software Portal site and the actions generated from
them, filtered to only actions affecting the logged-in operator's computers, in a
fixlet-grouped expandable table.

---

## Session Relevance (All OQs Resolved)

All session relevance strings confirmed. See `05-CONTEXT.md` OQ-1/OQ-2 sections for
canonical forms. Operator scope is handled natively by the Web Reports engine — no
explicit `whose` clause required on the action query.

**MIME fields confirmed:**
| Field | Carrier | Format |
|-------|---------|--------|
| `Associated_Roles` | Fixlets | Multi-value, joined ` | ` in relevance |
| `Associated_Roles` | Actions | Single value (one role per action), `concatenation ""` |
| `SmartRole_Source` | Actions | JSON string `{"id":"<fixletId>","sitename":"<site>"}` |

## Task 2 — Session Relevance Injection

Two `<Relevance>` blocks embedded in a `<script>` block. Each block is evaluated
server-side and its output replaces the tag inline; the served page contains the
actual data as string literals.

Output format: one `|||`-delimited line per record. JS splits on `\n` then `|||`.

```html
<script>
// Fixlet data — all role-aware fixlets in the Dereso Software Portal site
// One line per fixlet: id|||name|||site|||roles (roles joined " | ")
var _fRaw = "<Relevance>((item 0 of it as string & \"|||\" & item 1 of it as string & \"|||\" & item 2 of it as string & \"|||\" & item 3 of it as string) of (id of it, name of it, name of site of it, (if (exists mime fields whose (name of it = \"Associated_Roles\") of it) then ((if (exists value whose (not(it = \"\")) of it) then (concatenation \" | \" of values of it) else \"Nulled Role\") of mime fields whose (name of it = \"Associated_Roles\") of it) else \"General Access\")) of ((bes fixlets) whose ((exists fixlet flag of it) and (exists site whose (name of it contains \"Dereso Software Portal\") of it))))</Relevance>";

var fixletData = _fRaw.split('\n').filter(Boolean).map(function(line) {
  var p = line.split('|||');
  return {
    id:    p[0] || '',
    name:  p[1] || '',
    site:  p[2] || '',
    roles: (p[3] || '').split(' | ').map(function(r) { return r.trim(); }).filter(Boolean)
  };
});

// Action data — offer-type actions from role-aware fixlets, scoped to operator's computers
// One line per action: actionId|||name|||role|||sourceFixletId|||sourceSite
// Operator scope applied natively by Web Reports engine.
var _aRaw = "<Relevance>((item 0 of it as string & \"|||\" & item 1 of it as string & \"|||\" & item 2 of it as string & \"|||\" & (value of key \"id\" of json of item 3 of it) as string & \"|||\" & (value of key \"sitename\" of json of item 3 of it) as string) of (id of it, name of it, (if (exists MIME Field whose (name of it = \"Associated_Roles\") of it) then (concatenation \"\" of values of MIME Fields whose (name of it = \"Associated_Roles\") of it) else \"General Access\") of it, (if (exists MIME Field whose (name of it = \"SmartRole_Source\") of it) then (concatenation \"\" of values of MIME Fields whose (name of it = \"SmartRole_Source\") of it) else \"{%22id%22:%22%22,%22sitename%22:%22%22}\") of it) of (bes actions whose ((exists offer flag of it) and (exists MIME Field whose (name of it = \"Associated_Roles\") of it) and (exists MIME Field whose (name of it = \"SmartRole_Source\") of it))))</Relevance>";

var actionData = _aRaw.split('\n').filter(Boolean).map(function(line) {
  var p = line.split('|||');
  var srcId   = decodeURIComponent(p[3] || '');
  var srcSite = decodeURIComponent(p[4] || '');
  return {
    actionId:      p[0] || '',
    name:          p[1] || '',
    role:          decodeURIComponent(p[2] || ''),
    sourceFixletId: srcId,
    sourceSite:     srcSite
  };
});
</script>
```

**Notes:**
- `decodeURIComponent` handles the `%22`-encoded JSON fallback in `SmartRole_Source`
  (the default `{%22id%22:%22%22,%22sitename%22:%22%22}` decodes to `{"id":"","sitename":""}`)
- The `<Relevance>` tag content shown here uses `\"` escaping for the inner double-quotes
  because the tag sits inside a JS string literal in the actual `.beswrpt` file. In the
  `.beswrpt` CDATA block the real `<Relevance>` tag does NOT wrap in a string — the
  output is injected directly. The plan above shows the logical structure; the actual
  file structure puts `_fRaw =` and `</Relevance>` on separate lines outside the string.

**Actual `.beswrpt` Task 2 structure (CDATA, not JS string):**
```
var _fRaw = "
<Relevance>
(actual relevance here with unescaped quotes)
</Relevance>
";
```
Because the CDATA block is processed server-side before JS runs, the `<Relevance>` tag
is replaced with evaluated text and the JS variable assignment works normally.

## Task 3 — Client-Side JS: Join, Render, Filter

**`joinData(fixlets, actions)`**
- Returns `Map<fixletKey, { fixlet, actions[] }>` where
  `fixletKey = fixlet.id + '|' + fixlet.site`
- Matches actions to fixlets via `action.sourceFixletId + '|' + action.sourceSite`
- Fixlets with no matching actions get an empty `actions` array

**`renderReport(joined, roleFilter)`**
- Iterates over all fixlets in `joined` (sorted by `fixlet.name`)
- If `roleFilter` is set, skips fixlets whose `roles` array does not include the filter value
- For each fixlet, emits:
  - `<tr class="rpt-fixlet-row">` — fixlet name, site, role badges, action count
  - If `actions.length > 0`: one `<tr class="rpt-action-row hidden">` per action showing
    action ID, action name, action role badges, status, and a role-mismatch warning if
    the action's roles do not fully match the fixlet's roles
  - If `actions.length === 0`: one `<tr class="rpt-action-row hidden rpt-no-actions">`
    with "No actions affecting your devices"

**`toggleFixlet(fixletKey)`**
- Toggles `hidden` class on all `.rpt-action-row[data-fixlet=fixletKey]`
- Swaps `▶` / `▼` indicator on the parent row

**`applyRoleFilter(role)`**
- Called by role-filter `<select>` `onchange`
- Re-runs `renderReport(joined, role)` and replaces `<tbody>` innerHTML

**`initReport()`**
- Called on `<body onload>`
- Builds `joined` from global `fixletData` / `actionData`
- Populates role-filter `<select>` from `PORTAL_CONFIG.roles`
- Calls `renderReport(joined, null)` for initial unfiltered view
