## Task 3 — Client-Side JS: Join, Render, Filter

**`joinData(fixlets, actions)`**
- Returns `Map<fixletKey, { fixlet, actions[] }>` where
  `fixletKey = fixlet.id + '|' + fixlet.site`
- Matches actions to fixlets via `action.sourceFixletId + '|' + action.sourceSite`
- Fixlets with no matching actions get an empty `actions` array

**`renderReport(joined, roleFilter)`**
- Iterates over all fixlets in `joined` (sorted by `fixlet.name`)
- If `roleFilter` is set, skips fixlets whose `roles` array does not include the filter value
- For each fixlet, emits:
  - `<tr class="rpt-fixlet-row">` — fixlet name, site, role badges, action count
  - If `actions.length > 0`: one `<tr class="rpt-action-row hidden">` per action showing
    action ID, action name, action role badges, status, and a role-mismatch warning if
    the action's roles do not fully match the fixlet's roles
  - If `actions.length === 0`: one `<tr class="rpt-action-row hidden rpt-no-actions">`
    with "No actions affecting your devices"

**`toggleFixlet(fixletKey)`**
- Toggles `hidden` class on all `.rpt-action-row[data-fixlet=fixletKey]`
- Swaps `▶` / `▼` indicator on the parent row

**`applyRoleFilter(role)`**
- Called by role-filter `<select>` `onchange`
- Re-runs `renderReport(joined, role)` and replaces `<tbody>` innerHTML

**`initReport()`**
- Called on `<body onload>`
- Builds `joined` from global `fixletData` / `actionData`
- Populates role-filter `<select>` from `PORTAL_CONFIG.roles`
- Calls `renderReport(joined, null)` for initial unfiltered view
